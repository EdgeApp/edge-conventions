# Fix Code Skill

Implement fixes from a plan document by editing code. Changes are left unstaged for the user to review and commit.

## Prerequisites

This skill requires a plan document containing the fixes to implement. The plan document should contain:
- A list of changes to make
- For each change: the file(s) to modify and what needs to change

Plan documents are typically generated by:
- The `fix-pr` skill (from GitHub PR reviewer comments)
- The `review-code` skill (code review findings)
- Manual creation by the user

## Context Gathering

The user must provide:
1. **Plan document path**: A markdown file in `/tmp` or elsewhere containing the fixes to implement
2. **Repository**: The repository to work in (can be inferred from current directory)

Read the plan document and parse each actionable item.

## Implementing Fixes

For each item in the plan:

1. Read the relevant file(s)
2. Make the necessary code changes
3. Leave changes unstaged

After all fixes are implemented:

1. Run `yarn precommit` to verify the changes don't break linting or tests
2. Fix any failures that arise
3. Present a summary of all modified files to the user

## Important Notes

- **DO NOT COMMIT** - Leave all changes unstaged for the user to review
- **DO NOT PUSH** - This skill only edits files
- The user is responsible for staging, committing, and pushing changes
